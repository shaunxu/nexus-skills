# Forge app manifest developer guide

## Related tools

- forge-development-guide
- list-forge-modules
- forge-ui-kit-developer-guide
- forge-backend-developer-guide
- jira-service-management-assets-guide
- confluence-macro-developer-guide

The `manifest.yml` file is the configuration heart of your Forge app. It defines what your app does, where it appears, and what permissions it needs. Getting the structure right is crucial for a working app.

## Basic structure

Every manifest has three required top-level sections:

```yaml
app:
  id: 'ari:cloud:ecosystem::app/your-app-id'
  runtime:
    name: nodejs22.x

modules:
  # Your app's UI components and functions

permissions:
  scopes: []
```

## The `app` section

### Required properties

`id`: Your unique app identifier (generated by forge create) — DO NOT manually change it

```yaml
app:
  id: 'ari:cloud:ecosystem::app/your-app-id-uuid'
```

`runtime`: Specifies the Node.js version and optional limits. **Use the current Forge-recommended runtime** (e.g. `nodejs22.x`) for consistency. Agents and LLMs may suggest older runtimes from training data—always prefer the recommended version.

```yaml
app:
  runtime:
    name: nodejs22.x
    memoryMB: 512
    architecture: x86_64
```

## The `modules` section

Modules define where your app appears in Atlassian products. Each module type has specific properties, but most share common patterns. A module will have a `resolver` attribute if backend logic is implemented for it.

### JSM Assets modules

For Jira Service Management (JSM) apps that integrate with Assets CMDB, several specialized modules are available:

```yaml
modules:
  jiraServiceManagement:assetsImportType:
    - key: device-import
      function: import-resolver
      name: Device Import

  jiraServiceManagement:portalRequestCreatePropertyPanel:
    - key: device-selector
      function: selector-resolver
      title: Select Device

  jiraServiceManagement:queuePage:
    - key: inventory-management
      function: inventory-resolver
      title: Device Inventory
```

Important: JSM Assets integration requires specific scopes and architecture patterns. Use the jsm-asset-developer-guide for comprehensive guidance, including:

- Required permissions (for example, `read:cmdb-object:jira`, `read:cmdb-schema:jira`)
- AQL (Assets Query Language) integration
- Object lifecycle management
- Assets API service patterns

### Basic module structure

```yaml
modules:
  confluence:contentAction:
    - key: my-action # Unique identifier
      function: my-function # Links to function definition
      title: My Action # User-visible name

  function:
    - key: my-function
      handler: index.myHandler # Points to your code
```

### Common module properties

- `key`: Unique identifier within the module type. Use `<FirstPart>-<SecondPart>-<ThirdPart>` where `<ThirdPart>` is the feature name; `<SecondPart>` is optional for disambiguation.
- `function`: References a function defined under the `function` module
- `title`: Display name shown to users
- `icon`: Icon shown next to the module. Optional for most modules, but **required by the manifest schema (enforced by `forge lint`) for a few module types** — notably `jira:issuePanel` and `jiraServiceManagement:assetsImportType`. Omitting it on those will fail lint/deploy.

### Module placement notes

- `jira:globalPage` is limited to a **single instance per app** — declaring more than one entry fails deployment.
- For admin-only UIs, use `jira:adminPage` (appears under the Apps section of Jira admin settings) rather than adding a second global page.
- Confluence page modules (`confluence:globalPage`, `confluence:spacePage`) **require a `route` property** (a URL-safe slug). Jira page modules do **not** accept `route`.

### Display conditions

Control when modules appear using display conditions:

```yaml
modules:
  jira:issuePanel:
    - key: bug-panel
      function: panel-function
      title: Bug Analysis
      displayConditions:
        issueType: Bug
```

Complex conditions using logical operators:

```yaml
displayConditions:
  or:
    canDeleteAllComments: true
    and:
      projectKey: TEST
      not:
        issueType: Epic
```

### Keyboard shortcuts (Confluence)

Add keyboard shortcuts to supported Confluence modules:

```yaml
modules:
  confluence:contentAction:
    - key: quick-action
      function: my-function
      title: Quick Action
      keyboardShortcut:
        accelerator: ctrl+1
        description: Trigger quick action
```

Accelerator formats:

- Single key: `u`
- Key combination: `ctrl+1`
- Key sequence: `ctrl+1 shift+2`

## The `permissions` section

### Scopes

Declare OAuth 2.0 scopes for Atlassian product APIs:

```yaml
permissions:
  scopes:
    - read:confluence-content.summary
    - write:jira-work
```

For apps with no API access:

```yaml
permissions:
  scopes: []
```

Storage: Using Forge KVS (`@forge/kvs`) or the storage APIs in `@forge/api` requires the `storage:app` scope:

```yaml
permissions:
  scopes:
    - storage:app
```

### External permissions (egress)

Declare external domains and resources your app can access:

```yaml
permissions:
  external:
    fetch:
      backend:
        - api.example.com
        - '*.googleapis.com'
      client:
        - api.example.com
    images:
      - cdn.example.com
    scripts:
      - https://www.example-dev.com/script.js
    styles:
      - https://www.example.com/stylesheet.css
    fonts:
      - https://www.example.com/fonts.css
    frames:
      - https://www.example.com/embed/page
    media:
      - https://www.example.com/video.mp4
```

Each `fetch.backend`/`fetch.client` entry can be a plain domain string (above) or an object when you need extra metadata such as a data-residency category:

```yaml
permissions:
  external:
    fetch:
      backend:
        - address: api.example.com
          category: analytics
          inScopeEUD: false
```

### Content security policies

For apps requiring custom CSPs:

```yaml
permissions:
  content:
    styles:
      - 'unsafe-inline'
    scripts:
      - 'unsafe-hashes'
```

## Optional top-level sections

### `providers`

Configure OAuth 2.0 authentication with external services:

```yaml
providers:
  auth:
    - key: google
      name: Google
      type: oauth2
      clientId: ${GOOGLE_CLIENT_ID}
      scopes: ['profile', 'email']
      remotes: [google-apis]
      bearerMethod: authorization-header
      actions:
        authorization:
          remote: google-auth
          path: /oauth2/auth
        # ... other OAuth endpoints
```

### `environment`

Use environment variables in your manifest:

```yaml
environment:
  variables:
    - APP_ENV
    - API_BASE_URL

app:
  id: 'ari:cloud:ecosystem::app/${APP_ID}'
```

## Complete example

```yaml
app:
  id: 'ari:cloud:ecosystem::app/baf12188-3db6-4ec9-aa26-f85cecb62d05'
  runtime:
    name: nodejs22.x
    memoryMB: 512

modules:
  confluence:contentAction:
    - key: word-definer
      function: define-word
      title: Define Word
      keyboardShortcut:
        accelerator: ctrl+d

  jira:issuePanel:
    - key: status-panel
      function: show-status
      title: Custom Status
      icon: https://example.com/icon.svg # required for jira:issuePanel
      displayConditions:
        issueType: Bug

  function:
    - key: define-word
      handler: index.defineWord
    - key: show-status
      handler: index.showStatus

permissions:
  scopes:
    - read:confluence-content.summary
    - read:jira-work
  external:
    fetch:
      backend:
        - dictionary-api.com

remotes:
  - key: dictionary-api
    baseUrl: https://api.dictionary.com
    operations:
      - fetch
```

## Key tips

1. Validate keys: Module `key`s must be unique within their type and follow naming conventions
2. Check scopes: Use the minimum required scopes; check product docs for the endpoints you call
3. Test display conditions: They can be tricky; avoid overuse
4. External domains: Wildcards like `*.example.com` don’t include the apex domain; list it separately if needed

## Next steps

- Look up the specific module type in the Forge docs to see all available properties
- Review scope documentation for each product API you call
- Run `forge lint` after modifying the manifest
- If permissions, egress, or scopes change, upgrade your app installation
